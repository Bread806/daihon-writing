# Outline Builder

收到人類對角色的人物想像後，執行以下步驟，輸出完整的故事文件。
以下內容全部根據未完成的角色設計推斷，跟使用者一同討論進行補完。

---

## [Must]Step 1：讀取角色資料

閱讀使用者提供的角色設定（人物名、基本形象、客戶需求描述）。
如有既有故事文件（`.md`），一併讀取。

確認本次要產出的故事文件路徑：
`workspace/

---

## [Must]Step 2：確認所有欄位完備

故事文件需包含以下所有欄位。根據以下清單將已完成的內容勾選：

**角色小傳（劇中）**——須含以下子欄位，每項需附具體事件或例子，不可只有形容：
- [ ] 身分（性別、職業、年齡、與聽眾的關係）
- [ ] 性格特徵（面向）（角色的記憶點，讓聽眾一聽就認得出的特質）
- [ ] 價值觀（對人事物的看法與最重視的東西）
- [ ] 條件——擅長 / 不擅長（角色的能力邊界，決定施力點與限制）
- [ ] 課題（角色該克服的人生課題，與內在問題扣合）
- [ ] 情節鏈（角色行動的因果序列，每個轉折標註驅動因素：←價值觀 / ←阻礙 / ←轉折）
- [ ] 角色歷程（劇情開始前的背景事件，說明角色如何走到故事起點）

> **【故事起點邊界檢查｜Must】**
> 角色歷程最容易出的錯，是把劇情（情節）抄進背景裡，導致故事起點被往後推、ch1 失去開場張力。核心原則：**情節 ≠ 角色歷程**。
> - 角色歷程最後一行標出 `【故事起點】`，起點＝劇情「現在」的第一個場景（通常 ch1 開場）。
> - 凡是會在 ch1 之後被「演出來」的劇情事件（消費加碼、消失、歸來、和好⋯），都屬於情節，不要再抄一份進角色歷程。
> - 角色歷程寫的是「走到起點之前」的來歷與背景——它當然會影響後續劇情，但不等於把劇情複述一遍。

**故事設定**：
- [ ] 主角
- [ ] 主旨
- [ ] 內在問題
- [ ] 外在問題
- [ ] 想要（Want）
- [ ] 需要（Need）
- [ ] 行為與行動準則
- [ ] 大綱
- [ ] 喜惡
- [ ] 色情玩法

有缺漏的欄位，在此步驟先補完，或向使用者提問後補完。

---

## [Must]Step 3：完成人設
人設是角色的行為循環：
```
因為"價值觀"與"故事主要任務"衝突
=> 所以主角"行動"
=> 行動的結果觸碰主角的"喜惡"
=> 因為"價值觀"主角再"行動" (循環)
```
例如說：
```
酒吧老闆想和聽眾幸福的過日子（價值觀）但聽眾卻可能誤會自己是被通緝的犯人（引發故事主要任務）
=> 所以酒吧老闆用打賭的方式想套聽眾的話(主角做出行動)
=> 聽眾喝醉也打死不說，反而讓聽眾吐了很久導致身體不舒服，酒吧老闆覺得愧疚(與喜惡矛盾)
=> 為了和聽眾幸福的過日子(更觸及價值觀)，所以試著溫柔地照顧聽眾(再行動)
```

### [May] 因果鏈深化

完成行為循環後，可額外梳理一條從價值觀到主旨的邏輯鏈，強化故事設定的一致性：

```
價值觀 → 內在問題 → 課題 → 需要 → 主旨
```

此欄位非必填，但建議在角色設定複雜時使用。

## [Should] Step 5：為新角色輸出人設格式

輸出人設，結構須包含角色小傳子欄位：

```
## 角色小傳（劇中）

### 1. 身分
（職業、身份、與聽眾的關係）

### 2. 性格特徵（面向）
**面向標籤A**：具體描述 + 例子
**面向標籤B**：具體描述 + 例子

### 3. 價值觀
（對人事物的看法與最重視的東西）

### 4. 條件
- 擅長
  （列舉能力，附具體場景或例子）
- 不擅長
  （列舉弱點，附具體場景或例子）

### 5. 課題
- （角色需要克服的人生課題）
- 在情節中的顯現：（課題如何在劇情中體現）

### 6. 情節鏈
{
    行動描述                    <-- 驅動因素（←價值觀 / ←阻礙 / ←轉折）
    行動描述                    <-- 驅動因素
    ⋯⋯
}

### 7. 角色歷程
- （劇情開始前的背景事件，寫到故事起點為止）

---

外殼（第一印象）：...
內在（真實慾望）：...
外殼→內在的轉折點：預計發生在 Ch.X，觸發方式是 ...

標籤：...
面向：...（外表 _____，實際上 _____）
想要：...
需要：...
與聽眾的關係：...
行為模式：
  - 平常的習慣是 ...
  - 緊張時會 ...
  - 最在乎的事情是 ...
```

確認角色面向與轉折後，請使用者覆核，再繼續設計章節。

## [should]Step 6：套用 Style Guide 公式確認章節數與章節類型

視故事需要參照以下七章遞進範例，章節數可調整：

```
Ch.1 確立關係＋外殼建立
Ch.2 窺見內在（試探、遊戲、意外接觸）
Ch.3 阻礙建立
Ch.4 深入內在需要與價值觀
Ch.5 肢體升溫＋克服阻礙
Ch.6 情感與身體高點
Ch.7 收尾：確認、滿足、溫馨
```

如果當前劇情特別簡短或有其他考量，可調整為 5～6 章，但需說明理由。
輸出確認章節數，以及外殼→內里的轉折點落在哪一章。

---

## [Must]Step 7：設計各章節具體細節

對每一章輸出以下格式，不可只填一行標題。
**每個行動必須包含角色的具體台詞**（用「」標記），不可只寫動作描述：

```
### Ch.X 章節名稱（互動或服務類型）

章節大綱：
（這章要完成的敘事目標——聽眾看完會感受到什麼？發生了什麼推進？）

章節主旨：
（這章要傳達的核心訊息）

想要：
（主角在這章的具體小目標）

目標：
（這章對整體故事的功能——讓聽眾明白什麼、鋪墊什麼）

行動：
{
    1. 行動描述
    「角色的具體台詞」
    「角色的具體台詞」

    2. 行動描述
    「角色的具體台詞」

    3. 行動描述
    「角色的具體台詞」
    「角色的具體台詞」
}
```

全章設計完成後，再次確認：
- [ ] 服務聽眾章節的章節有哪些
- [ ] 已列出各章互動或服務內容
- [ ] 跨章感官不重複：相鄰章節的主感官（聽覺／口腔／手部／插入⋯）有區隔，避免玩法雷同。
- [ ] 外殼→內在轉折點有在設計中體現
- [ ] 故事起點＝ch1 開場，沒有情節事件被誤寫進角色歷程
- [ ] 終極目標（Want 是否達成、Need 往前走了沒）明確
